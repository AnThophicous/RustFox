# TQ1_0 and Layer-Contiguous FOXPACK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Increase CPU inference throughput for supported GGUF models by adding integer SIMD GEMV for Q4_K/Q6_K and TQ1_0, then overlapping contiguous streamed layer reads through a GGUF-compatible `.foxpack` repack.

**Architecture:** Q4_K/Q6_K and TQ1_0 keep portable scalar paths as references and add SSE2 integer kernels selected at compile time on x86, so no unsupported instruction is executed on non-x86 targets. Activations are quantized once per GEMV call and reused across all rows. `.foxpack` is still a valid GGUF file: the original header and metadata are retained, tensor offset fields are patched, and tensor payloads are copied in embedding/layer/output order. The stream backend recognises the `.foxpack` layout, loads one physically contiguous layer span into a slot, and a dedicated prefetch worker can load the next layer while the current layer computes.

**Tech Stack:** C11, CMake, GGUF v2/v3, platform `pread` abstraction, SSE2 intrinsics on x86, existing RustFox thread pool and test harness.

## Global Constraints

- Preserve all pre-existing uncommitted changes in `forward.c`, `kernels.c`, `model_internal.h`, `ops.c`, `tokenizer.c`, and the temporary file created by the concurrent Claude session.
- Keep the original GGUF readable and byte-for-byte unchanged; repack writes a separate output path.
- `.foxpack` must remain parseable by `fox_gguf_open` and must not change tensor bytes, dimensions, types, or metadata.
- TQ1_0 vectorisation must produce the same result as `fox_tq1_dot_i8_scalar` for randomized valid blocks; scalar fallback remains available.
- Q4_K/Q6_K integer kernels must stay within the existing quantized-GEMV numerical tolerance against the scalar float kernels; non-SSE2 builds retain the old path.
- Stream resident bytes must never exceed the configured budget, including a whole layer span.
- Prefetch owns its worker lifecycle, never exposes a buffer before the read completes, and never evicts a live lease.
- Do not claim a speedup without a fresh benchmark on an available Linux/toolchain environment; the current Windows shell has no CMake/compiler.
